# frontend

냉장고 한끼의 React 앱. 프로젝트 전체 설명은 [저장소 최상단 README](../README.md)에 있다.

## 명령

```bash
npm ci && npm run dev
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | `tsc -b && vite build` |
| `npm test` | Vitest |
| `npm run lint` | oxlint |
| `npm run gen:api` | `openapi.json`에서 API 타입 재생성 |

## API 타입은 손으로 쓰지 않는다

`src/api/schema.d.ts`는 생성물이다. 백엔드 응답 모양이 바뀌면 이 순서로 갱신한다.

```bash
cd .. && ./.venv/Scripts/python.exe scripts/dump_openapi.py
```

```bash
npm run gen:api
```

명세를 배포된 서버가 아니라 **저장소 코드에서** 뽑는 이유가 있다. 처음에는 배포된 V2
백엔드에서 받았는데, 그 명세에는 V3에서 이미 지운 엔드포인트가 남아 있었다. 타입으로
불일치를 잡겠다면서 정작 지금 코드가 아닌 것을 기준으로 삼은 셈이었다. CI가 이 어긋남을
검사한다.

`openapi-typescript`는 TypeScript ^5만 받는데 이 프로젝트는 6을 쓴다. 그래서 의존성으로
넣지 않고 `npx`로 격리 실행한다.

## API 주소

`VITE_API_BASE`로 정한다. 기본 로컬 개발은 이 저장소의 백엔드(`:8001`)를 본다.

로컬 DB 설정이 없는 PC에서 기존 배포 API에 연결하려면 `frontend/.env.development.local`에
아래 값을 넣고 `npm run dev`를 실행한다. 이 파일은 Git에 포함되지 않는다.

```env
VITE_API_BASE=/api
DEV_API_PROXY_TARGET=https://naengjango-hankki-v2-api.onrender.com
```

프론트 개발 서버가 `/api` 요청을 전달하므로 백엔드 CORS 설정 변경이 필요 없다.
가입·로그인·저장 요청은 실제 서비스에 반영된다. 빌드는 기존 배포용 `VITE_API_BASE` 설정을
그대로 사용한다. 로컬 백엔드로 돌아가려면 이 로컬 설정 파일을 제거하고 개발 서버를 재시작한다.

### 테마 전체보기

홈의 전체보기는 `/themes/:themeKey?month=10`에서 같은 테마를 20개씩 조회한다.
API의 `GET /recommendation/recipes/themes`에 `theme`, `month`, `limit=20`,
`offset=0/20/40…`을 전달한다. 기존 홈 미리보기는 테마별 10개를 유지한다.

개발 서버가 배포된 API를 프록시하는 경우, 해당 서버에도 테마 페이지 조회 변경이
반영되어야 전체보기가 동작한다. 구형 서버는 `theme`와 `offset`을 무시하므로
화면은 잘못된 미리보기를 전체 목록으로 표시하지 않고 조회 실패와 재시도를 안내한다.

### 즐겨찾기 미리보기와 전체 목록

마이(`/my`)는 최근 저장한 레시피 3개를 작은 사진의 가로 목록으로 보여준다.
4개 이상이면 더보기로 `/my/favorites`에 이동해 전체 목록을 본다. 두 화면에서
해제·되돌리기를 지원하며, 읽기 실패는 빈 목록과 구분해 다시 불러올 수 있다.
기존 `GET /favorites/{user_id}`와 toggle API를 사용하며 새 서버 배포나 DB 변경은 필요 없다.
사진은 작은 화면에서 72px, PC에서 88px로 유지한다.

### 오늘의 영양과 식사 기록

레시피 상세의 `먹었어요`에서 먹은 양(0.5·1·1.5·2인분)을 선택해 저장한다.
마이(`/my`)의 `오늘의 영양`에서 영양소별 합계와 오늘 먹은 음식, 양 수정·기록 취소를 제공한다.
나트륨은 채우는 목표와 분리해 상한 대비로 표시하며, 정보가 없는 영양소는 부분 합계임을 알린다.

`POST /meals`, `GET /meals/today`, `PUT /meals/{id}`, `DELETE /meals/{id}`를 사용한다.
로그인 토큰으로 본인의 기록만 처리하며, 생성 요청 ID를 재사용해 통신 재시도로 인한 중복을 막는다.
자정은 서버의 한국 시간 기준이다. 화면을 열어두거나 다른 탭에서 돌아올 때 자동 재조회하고,
자정 후 조회 실패 시 어제의 값을 오늘 값으로 표시하지 않는다. 과거 기록은 DB에 보관한다.

이 기능은 **DB 마이그레이션 013과 새 백엔드가 필요하다**. 개발 서버가 기존 배포 API를
프록시한다면 해당 서버에도 변경이 배포돼야 저장할 수 있다. 로컬 확인 시에는 마이그레이션을
적용한 개발용 DB로 API를 실행하고 프록시 대상을 그 API 주소로 설정한다.

## 화면

`src/routes/`에 한 화면당 한 파일이다. 각 파일 상단 주석에 **그 화면이 왜 그렇게
생겼는지**를 적어뒀다 — 실제 데이터를 보고 시안에서 바꾼 것들이라 코드만 봐서는 알 수
없다. 예를 들어 홈의 "인기 레시피"는 운영 DB의 좋아요가 4개뿐이라 "레시피 둘러보기"로
바뀌었다.
